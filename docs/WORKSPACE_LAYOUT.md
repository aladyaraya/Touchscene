# 项目目录与本地交付

此仓库是手机相机版的主维护入口。本地若另存原始开发参考副本，
不要把两边交替作为发布来源；其他开发者无需取得该副本。应用显示名为“触景Touchscene”，包名仍为
`com.touchscene.minimal`，不影响原有数据和覆盖更新。

```text
android/       Android 源码、资源、测试、Wrapper 和必要原生库
docs/          架构、配置、验收、规格、图标与维护说明
tests/         可独立运行的源码、图标和原生依赖检查
tools/         图标生成等维护工具
.github/       无云密钥的构建与检查
artifacts/     仅本地输出，已忽略提交
  internal/    当前内部安装包；history/ 只保留必要回退包
    testing/   最新测试包，等待用户恢复专项回归
    build-support/ 内部配置构建辅助
  evidence/    私有诊断截图、XML及只读诊断工具
  maintenance/ 整理清单和历史验证报告
```

`artifacts/` 不能用于 GitHub 源码同步：内部 APK 可能含本地 API 配置。
`artifacts/`及其中的本地索引、内部配置辅助和整理记录仅在维护机上按需保存，
不随 clone／ZIP 提供。需要重新构建时按根目录 README 操作；
未构建或清理后 `android/app/build/` 不存在属正常现象。
原生 APK 检查需要先重新构建，不能用跳过缺包来获得通过。

原源码、算法、模型、包名、Gradle 版本和原生库均未因目录整理而变更。
本次精简不改应用代码。此前获准的改名、触摸、描述和振动修复见
[修复记录](TOUCH_CONTOUR_FIX.md)，不借整理扩大代码修改范围。
`.git`、本地配置、私有签名和必需原生文件不属于可删除缓存。
目录整理本身未触发远端发布；之后由用户另行授权同步到 `only-for-android`。

## 内部文件保留约定

- `internal/`只保留当前已确认版本；`history/`仅保留必要回退版本，并注明已知问题。
- `internal/testing/`用于待回归的测试包，不把“已经编译”写成“真机已经通过”。
- `evidence/`保存必要、获准采集的私有诊断材料，不公开用户照片、设备标识或触摸轨迹。
- `maintenance/`保存本地整理清单与验证报告；已存在的报告不能冒充本轮新测试。

原始记录、当前包、必要回退包、源码、原生库、Git元数据和私有配置均应保留。
构建缓存是否实际删除以本地操作记录为准，不影响源码发布，也不计作测试通过。
