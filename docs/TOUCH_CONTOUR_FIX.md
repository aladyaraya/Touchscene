# 触摸命中与照片外框修复 · 2026-10-16

## 对照原版的结论

对照最初仓库 main `3eea391f32985ddd79f94a560fc1dabc27aa5b8c`，修复前
OpenCV 边缘、GrabCut、主体/边界生成、轮廓带、触觉 View、YUV、调度和振动源码均一致，
OpenCV 原生库也一致。但源码相同不代表原有缺陷不存在，也不代表不同输入照片效果一致。
手机现在输入 CameraX 照片，而原版输入外部相机解码帧。

本次真机发现原版 View 在按真实图像坐标采样之前，先用固定 64×48、4:3 网格判断触点；
这会把竖图上方、下方的可见部分判为背景。系统记录表明中部有效位置仍收到原版
80ms 开 / 40ms 关的重复振动请求，不能据此声称持机者一定能感觉到振动。

原主体边界计算会把贴住画布最外圈的前景算为边界。用户确认问题是整张照片最外圈／留白，
而不是图中的桌沿等真实背景边缘。

## 本次明确修改

- TactileMapView：非粗网格显示层独立使用其真实图像坐标采样，不被粗网格空点提前截断。
- ContourBandRasterizer：显示轮廓带用圆形行区间并集替代逐像素重复绘圆。
  未开启外框过滤时，结果必须逐像素等于原 ContourHapticMask，不降低精度。
  View 开启过滤，仅跳过 x=0/y=0/x=w-1/y=h-1 的边界种子；不删除连接到边框的整个主体，
  距画布一像素的真实边界仍保留。原分割数组不修改。
- 预览页底部增加当前层名，默认原图及 原图→边缘→轮廓 顺序不变。

未改 OpenCV、GrabCut 参数、原轮廓带源文件、原主体/边界提取、分辨率、图层顺序或振动波形。
不是语义分割升级：这项外框处理不能保证消除靠近边框的所有背景，也不能识别任意主物体。

## 速度与验证边界

修复前现场记录到两次本地图处理约 1.2s、2.0s；这是两次观察，不是有代表性的 P95。
