# 统一无障碍操作需求

状态：原开发阶段已批准并实现的规格；2026-10-15。适用工程：`android/`，基线 `3eea391f32985ddd79f94a560fc1dabc27aa5b8c`。统一触区变更优先于旧的圆形麦克风和“语音拍照不冻结”要求，其余原有流程继续保留。最新验证边界见 ../../ACCEPTANCE.md。

## 目标与范围

让用户通过大面积、位置稳定的入口打开手机相机或本地图片，并在相机页用一个大按钮完成单击与按住说话。语音描述解释原图内容；用户主动扫描固定地图，以全机振动探索平面结构。单马达不是局部触觉像素，也不代表已证明识形效果。

用户故事：作为视障或低视力用户，我希望不寻找小麦克风即可发出拍照／录像命令，并让保存的照片、触觉图与描述来自同一画面。

## EARS 验收条件

| 编号 | 条件与系统响应 |
|---|---|
| U01 原生处理 | 当应用处理受控图片时，系统应成功加载 OpenCV 及同 ABI 的 C++ 运行库，并实际经过原 `OpenCvImageProcessor`；测试应区分成功处理与异常后的降级结果。 |
| U02 首页 | 当首页显示时，系统应将可用内容区上下各 50% 作为大入口，上半打开手机相机、下半打开本地图片；隐藏原厂专用入口且不扩张 legacy 控件。 |
| U03 相机布局 | 当相机页显示时，系统应保留顶部 75% 地图区，并用底部 25% 的唯一大按钮代替圆形麦克风及原独立操作区；相机页不出现上传入口。 |
| U04 单击 | 当用户在 LIVE 模式短按大按钮时，系统应真实拍摄、冻结并自动描述；当用户在 EXPLORING 模式短按时，系统应返回 LIVE；当正在录像时，单击仅提示长按说“停止录像”，不拍照或停止录像。 |
| U05 长按 | 当用户按住大按钮达到 500 ms 时，系统应只开始收音，不自动拍摄；未达门槛的有效短按才触发 U04。长按成立后的松开不得补发普通 click。 |
| U06 收音反馈 | 当用户按下按钮时，系统应给出一次 35 ms 短震；当开始录音前，系统应停止振动与播报；录音期间不得持续震动或朗读录音提示。 |
| U07 释放与取消 | 当有效录音达到 300 ms 且不足 30 s 后松开时，系统应仅提交一次 ASR；当录音太短、达到 30 s、移出、多指、取消、后台或离开页面时，系统应丢弃录音且不拍摄、不上传 ASR、不补短按。30 s 从真正开始录音时计算。 |
| U08 权限与过期 | 当授权结果返回、页面恢复或旧异步结果到达时，系统不得自动开启麦克风；旧录音、旧清理或旧描述不得覆盖新一轮状态。 |
| U09 同图拍照 | 当语音命令命中“拍照／拍一张”时，系统应只拍摄并保存一张照片，随后将同一个返回 URI 送入原图处理、冻结／刷新及自动描述链；无须先返回 LIVE，也不得为识图再拍第二张。 |
| U10 录像同义 | 当命令命中“摄影／录像／录音”时，系统应进入同一个录像流程；当命中相应“停止”命令时，应停止同一录像。此处“录音”不是新增音频文件功能。 |
| U11 描述调度 | 当当前图片的描述在收音或指令处理期间返回时，系统应保留一个待播结果，在录音清理及命令反馈结束后播放；旧图、后台结果应丢弃。每次进入页面的第一段描述追加“双击画面，可在原图、边缘、轮廓间切换。”；后台恢复不重置提示预算。 |
| U12 保留与可达性 | 当用户使用本地图片、图层切换或触觉扫描时，系统应沿用原页面、原 OpenCV 算法、坐标和波形；大按钮应提供单击和按住操作说明。真实 TalkBack 操作、听音、振感与识形效果必须单独人工验收。 |

## 非目标及证据边界

- 不引入新服务、数据库、账户、分割模型、重写触觉算法或三页式新 UI；不修改现有三个百炼适配器。
- 不恢复被主动按住打断的已开播描述；U11 只涉及收音／处理期间才返回的待播结果。
- 不修改旧字符串；新增文案使用独立 `unified_*` 资源，保留已有 `hold_*` 历史资源。
- 主代理已在真机确认原生 OpenCV 缺少 C++ 共享运行库依赖。本轮必须先修依赖，再验证实际原生处理。先前 40 项仪器测试是旧软件检查，不能证明该原生算法已执行，更不能证明人耳听到或手感有效。
- 本文记录已批准目标，不声明本轮构建、设备测试或人工验收已经通过。当前状态见 `tasks.md`。
